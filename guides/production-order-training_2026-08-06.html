3.2 Statuses and actions observed

The BOM screen showed an Approved row and actions labelled Approve Revision and Use for Planning. The production-order sequence showed Created, Released, Active, and Completed states across the relevant screens.

Updated 2026-08-13 — official meaning now available, from session help filed after this review was first written:

  • Created, Printed, and Released are the order statuses named directly in Production Orders tisfc0501m000's opening description — the recording's sequence uses real, named statuses, not informal labels.
  • Active is defined precisely: the Actual WIP Transaction Done field states that once a WIP transaction has occurred against the order, "the order status has become Active." A material issue is a WIP transaction, so the order in this recording became Active because material was issued against it — not from Release alone.
  • Use for Planning and Use for Costing are real check boxes, defined the same way on both the BOM (tibom3100m000) and the routing (tirou4100m000): if selected, that record is the one LN actually uses for planning, or for costing, respectively. Only one BOM per item and site can be used for planning; only one BOM per product can be used for costing — and the same one-at-a-time rule applies to routings used for costing. Approve Revision is a real Actions-menu command that records Approved By and Approved On on the revision; the help does not state that approval is a hard precondition for using the BOM elsewhere in the flow, so that stronger reading remains unconfirmed.

Source: LN training environment, verified from the 2026-08-06 recording — the source on file, the source on file, the source on file, and the source on file; Infor LN help for Production Orders tisfc0501m000, Field Information (Order Status, Actual WIP Transaction Done); Infor LN help for Job Shop Bills of Material tibom3100m000 and Infor LN help for Job Shop Routings tirou4100m000, Field Information (Use for Planning, Use for Costing, Approve Revision).

3.3 Reporting production progress

At 56:20 the presenter entered 1 as Additional Completed in Report Operations Completed tisfc0130m000. Infor session help confirms that this session reports production progress through completed or rejected quantities for successive operations; for the last operation it can book the completed product into inventory.

At 57:20 Report Orders Completed tisfc0120s000 showed Quantity Delivered as 1; after the save, Production Orders tisfc0501m000 showed the order as Completed. Infor session help for Production Orders identifies Quantity Delivered as the finished-goods quantity posted to inventory. The next dialog, Close Production Orders, exposed its session code as ticst0201m000 (recorded here as ticst0210m000 until the 2026-08-13 correction).

Sources: Infor LN help for Report Operations Completed tisfc0130m000, opening description; Infor LN help for Production Orders tisfc0501m000, Field Information; LN training environment recording and screenshots dated 2026-08-06.

3.4 Material issue demonstration is not a validated procedure

The screen showed Material to Issue for Production Orders ticst0101m100, the Initiate action, and a warehouse quantity changing to 1. During this segment the presenter explicitly said to ignore an incorrectly selected warehouse/shop-floor warehouse path. Therefore this segment is evidence that the screen and action exist, but it is not a clean end-to-end procedure and must not be promoted into a Work Guide or Scenario Guide.

Updated 2026-08-13 — the underlying mechanism is now documented, from session help filed after this review was first written. Material to Issue for Production Orders ticst0101m100 maintains material quantities that must move from the warehouse to the production center. The Initiate action relates to a distinct session, Initiate Inventory Issue tisfc0207m000, which unblocks the material's warehouse order line so warehouse staff can begin the outbound procedure — generate advice, pick, ship to the job shop. Two check boxes decide how much of that is automatic:

  • Direct Initiate Inventory Issue — if selected, the warehouse order line unblocks automatically on production-order release, and tisfc0207m000 never needs to be run by hand.
  • Direct Process Warehouse Order Line — if selected, the entire outbound procedure runs automatically once the line is unblocked; if cleared, the Activities by Warehousing Order whinh2104m000 settings decide which of those outbound steps are automatic versus manual.

This is real official meaning for the mechanism, but not a statement about this environment's configuration — whether either check box is selected for Company 4100 is still unconfirmed.

Source: LN training environment, verified from the 2026-08-06 recording at 54:48–55:28; the source on file. This segment is not a valid procedure; the clean 2026-08-11 run superseded it. Infor LN help for Material to Issue for Production Orders ticst0101m100, Field Information (Direct Initiate Inventory Issue, Direct Process Warehouse Order Line).
