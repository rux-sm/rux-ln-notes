Evidence: the source on file; the source on file.

The process shape is independently supported by the Infor LN Sales Orders user guide and the Infor LN Outbound and Shipments user guide. The verified environment-specific route remains the source on file; this meeting does not replace it.

3.2 Warehousing procedures control automation

The trainer explained that the warehousing order type and its linked procedures determine which activities apply and whether they run manually or automatically. Infor help confirms that Activities by Procedure whinh0106m000 selects activities for a warehousing procedure and that its Automatic setting determines whether an activity runs automatically after the preceding activity.

Source: Infor LN help for Activities by Procedure whinh0106m000, opening description and Field Information; the Infor LN Outbound and Shipments user guide, chapter 2, “Automatic or manual execution of activities.” The verified Company 4100 outbound configuration is in the source on file, which carries the order-type 20 activity list.

3.3 Learning method: trace defaults to their source

The trainer directed trainees to investigate why warehouses, prices, and automatic actions defaulted as they did, beginning with the item master and the session's Help control. This is a reusable consulting method: separate a value observed in this company from the vendor definition of the field, then use session help to establish meaning.

No specific default source was settled in the meeting. Item data, business-partner data, order type, sales user profile, and user profile were proposed as questions to investigate, not conclusions.

Updated 2026-08-13 — one of these is now answered. For Sales Order Type specifically, tdsls4100m900's help confirms the default comes from the order type assigned to the Sold-to Business Partner tccom4110s000, falling back to the order type on the current user's Sales User Profile tdsls0139m000 if the customer has none. See the source on file section 3.1, where this rule closes the same open question raised there. The other proposed sources (item data, general business-partner data) remain untraced.

3.4 Production master-data exercise and BOM loop

The participants created or reviewed a manufactured item, a job-shop bill of material, and a routing, then attempted to create a manual production order. Validate Job Shop Routing from Job Shop Routings tirou4100m000 produced a report for product 9010-2010, routing 0, revision 000001, stating Loop found in Multilevel BOM and showing a loop path.

Evidence: the source on file.

Updated 2026-08-13 — partially resolved, from session help filed after this review was first written. Approve Revision, Use for Planning, and Use for Costing are all real, confirmed actions/fields: Use for Planning and Use for Costing are one-at-a-time flags (one BOM per item/site for planning, one BOM per product for costing — and the equivalent rule for routings), and Approve Revision records who approved a revision and when. Still unconfirmed: what "Loop found in Multilevel BOM" actually checks and the supported correction route — tirou4100m000's own help does not document the Validate action or this specific message at all, so the diagnosis-and-correction question stays open.

Source: Infor LN help for Job Shop Bills of Material tibom3100m000, Infor LN help for Job Shop Routings tirou4100m000, Field Information.

3.5 Clean material-issue rerun verified

The recording provides the controlled rerun that the earlier transcript could not prove:

  1. Production order 010000744 for item 9010-2010, quantity 1, was visible in Production Order tisfc0101m100 with BOM JB0000238 revision 000002, routing 0 revision 000001, warehouse ADNA02 RAW MATERIALS, two operations, and status Created.
  2. Release Orders was invoked from Production Orders tisfc0501m000 — per that session's own help, filed 2026-08-13, this is literally "release production orders to the job shop," and it is what changes the status to Released.
  3. In Material to Issue for Production Orders ticst0101m100, material 100400 showed Estimated 2.000, Actual Qty 0.000, and To Issue by Warehouse 2.000 after release.
  4. Warehousing Orders whinh2100m000 showed a planned production receipt and an open production issue for order 010000744. The Issue detail (whinh2100m100) showed order type 30- Production (Out), source ADNA02 RAW MATERIALS, and destination work center A1000.
  5. Outbound Line Status Overview whinh2129m000 showed ordered quantity 2, with Generate Outbound Advice and Release Outbound Advice both unfinished and non-automatic. The recording then shows those two actions being run manually.
  6. The Issue warehousing order reached Shipped with ordered/advised quantity 2. Back in ticst0101m100, the production order was Active, Actual Qty 2.000, To Issue by Warehouse 0, and To Issue 0. tisfc0501m000's help, filed 2026-08-13, confirms Active specifically means a WIP transaction — such as this material issue — has occurred against the order.

Evidence: the source on file; the source on file; the source on file; the source on file; the source on file; the source on file; the source on file; the source on file; the source on file.

Updated 2026-08-13 — the mechanism behind step 5 is now sourced. ticst0101m100's help describes two check boxes that govern exactly this: Direct Initiate Inventory Issue (unblocks the material's warehouse order line automatically on release, versus needing Initiate Inventory Issue tisfc0207m000 run by hand) and Direct Process Warehouse Order Line (runs the whole outbound procedure automatically once unblocked, versus falling back to Activities by Warehousing Order's manual/automatic settings — the same session already cited in section 3.2). Generate and Release Outbound Advice needing to be run manually here is consistent with Direct Process Warehouse Order Line being off for this material, but which check box is actually set for Company 4100 is still not confirmed .

3.6 Production completion was assigned, not demonstrated

The facilitator described the remaining exercise: complete the operations, receive the end item through the receipt warehousing order, and report the production order complete. The meeting ended before those steps were performed.

Infor help confirms the limited meanings that Report Operations Completed tisfc0130m000 records production progress and that Quantity Delivered is the finished-goods quantity posted to inventory. Sources: Infor LN help for Report Operations Completed tisfc0130m000, opening description and Field Information; Infor LN help for Production Orders tisfc0501m000, Field Information.

3.7 Planning before subcontracting

A participant asked whether to study subcontracting or planning next. The group chose a full planning walkthrough first because subcontracting would require more setup and the available trainer reported limited recent subcontracting experience.

The planning discussion is partly supported by official sources: Default Supply Source determines the item's default supply method when on-hand inventory is insufficient, and Enterprise Planning can generate planned production and purchase orders before transfer to execution packages. Sources: Infor LN help for Item Detail tcibd0501m100, Field Information; the Infor LN Order Planning user guide, “Selecting Supply Sources” and “Transferring Planned Orders.”

The subcontracting explanation remains narration only.

  2. Teach execution and planning as separate learning blocks at first.
  3. Continue the production-order exercise after the meeting rather than treating receipt and completion as performed.

Methodology and process notes

  • The recording establishes visible session codes, records, quantities, statuses, and actions; transcripts preserve discussion sequence and narration.
  • Treat troubleshooting mistakes as test cases. The mismatched item/routing and BOM loop identify useful validations, but an improvised workaround is not a reusable procedure.
  • Keep the manual production-order exercise distinct from the later planning exercise.
  • Trace defaults rather than memorizing them: identify the observed value, locate the owning data or procedure, then use Infor help for its meaning.
